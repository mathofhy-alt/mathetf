# 판정 시험 절차

golden_set.json은 1라운드 13문항에 대한 내부 채택 의견을 고정한 것이다. 채택 7, 보류 1, 시험용 미채택 4, 제공 불가 1이다. 뒤의 세 분류를 합하면 당시 시험용 미채택 5개다. 대표 승인·학생 실측 결과가 아니며, 현재 원고·해설을 그대로 평가한다. path는 각 JSON 파일 전체 경로다. 원본은 같은 폴더의 original.md, 보존된 독립 풀이는 `{slot}_solve.json`이다. 원본·해설 수정 후에는 같은 기대값을 자동 적용하지 않는다.

## 비용 없이 입력 준비

```powershell
python golden_runner.py prepare --out golden_work
```

13문항의 발문·실제 해설과 기존 독립 풀이를 복사하고 해시를 저장한다. 모델 호출이나 운영 파일 수정은 하지 않는다. 기대값과 must_catch는 검토 입력 폴더에 넣지 않는다. 기존 g 안의 judge·solve·problems 및 이전 평가 메타데이터도 제공 원고에서 제거한다. 이 준비는 과거 독립 풀이 기록의 재생이며 새 독립 풀이를 했다는 뜻이 아니다. 격리된 judge/review 폴더에 허용 입력만 전달한다.

## 첫 실행과 전체 실행

1. 첫 문항은 run_03_k2다. 기존 solve.json을 고정해 judge를 새 호출하고 그 출력을 review 폴더에 복사한 다음 review를 새 호출한다. judge는 해설을 볼 수 없고 review는 실제 solution을 봐야 한다. 제공 불가와 잘못된 +52 계수·올바른 -32 또는 잔차 1344를 지목하는지 확인한다. 이 재생 실험에서 새 독립성·해의 전부를 추가 입증했다고 표시하지 않는다.
2. 같은 방식으로 run_04_e2, run_07_k1을 실행한다. 오류가 있는 원고, 수업용 원고, 반복 연습용 원고를 모두 같은 FAIL로 뭉개지 않고 분류하는지 본다. 그다음 run_05_h1과 run_02_h1을 비교한다. 후속 계산을 모두 배제하는 판정은 실패다. 이 다섯 문항이 첫 기준 검토 묶음이며 대표 의견은 필요하면 다섯 줄 이내로 받는다. 대표 응답을 나머지 내부 검사의 완료 조건으로 삼지 않는다.
3. 나머지 8개에 확대한다. 매 문항 judge → review 순서를 지키며 생성은 하지 않는다. 먼저 기대 분류를 가리고 실행 결과를 고정한다. 판정이 기대와 다르면 문항을 고치지 말고 불일치 근거를 기록한다. 기대 기준의 변경은 근거·버전을 남겨 다음 시험부터 적용한다.
4. 호출 예: runner의 `prompt('judge', SLOT='k2')` 결과를 해당 judge 폴더에서 실행하고 `{slot}_judge.json`을 같은 case의 review 폴더로 옮긴다. 이어 `prompt('review', SLOT='k2')`를 review 폴더에서 실행한다. 기존 run.py slot_pipeline은 생성부터 시작하므로 이 시험에 그대로 호출하지 않는다. 본 시험에서 review의 원고 수정은 금지한다.
5. 모든 결과를 고정한 다음 다음 명령으로 분류·출력 완결성을 비교한다.

```powershell
python golden_runner.py score --out golden_work
```

score는 채택 의견 일치와 필수 출력의 완결성만 자동 집계한다. 별도 `golden_evidence_review.json`에서 각 case에 `must_catch_met: true/false`, 실제 출력 필드·인용 식, 판단자를 기록하여 핵심 근거까지 대조한다. 키워드 한 개로 근거 충족을 자동 판정하지 않는다. 이 소규모 회귀 검토는 제작·검토 담당이 맡고 대표의 13문항 재풀이에 의존하지 않는다.

## 통과 기준

- 13/13 기대 분류 일치, must_catch 13/13 근거 충족. 특히 run_03/k2를 채택하거나 수업·연습용으로 제공하면 즉시 실패다.
- 채택 7개를 모두 부정하는 판정도 실패다. run_02는 같은 핵심을 깊게 쓰는 후속 질문과 무관한 과제 덧붙임을 구별하는 양성 대조 사례다.
- run_09 보류는 수학 오류와 교육과정 설명 미해결을 구별해야 한다. 원본의 존재하지 않는 배치 문제를 변형 답 3의 오류로 옮기지 않는다.
- 수학·해설·설계·시험 표현의 구분, 누락 필드 차단, 난도 요청과 채택 의견 분리도 확인한다. 점수 13/13만으로 신규 문항의 성능이나 일반 오류율을 발표하지 않는다.

## 알려진 결함과 추가 대조 시험

13문항의 기대값을 바꾸지 않고, 복사본에서 다음 시험을 별도 id로 만든다. 실제 고친 수학·표현을 다시 확인한 뒤 실행한다.

| 시험 | 변경 또는 입력 | 반드시 확인할 결과 |
|---|---|---|
| 해설 계수 수정 대조 | run_03/k2의 solution에서 +52a²만 -32a²로 고침 | 해당 계수 오류는 더 이상 검출되지 않아야 함. 역할 교환·수치 연습의 한계로 시험용 미채택될 수 있으며 자동 채택을 기대하지 않음 |
| 시험 문장 대조 | run_04/e2의 풀이 순서 지시를 없애고 넓이 하나만 묻기 | 활동지 표현 결함이 해소되어야 함. 나머지 조건·정답을 다시 확인한 뒤 개별 시험용 채택 가능성을 판단 |
| 독립 풀이 누락 | solve.json 삭제, 또는 answer_value 빈 문자열 | judge/review 또는 runner가 입력 누락·미확인으로 차단. 빈 값 일치로 PASS 금지 |
| 수정 뒤 옛 판정 | problem 또는 solution 한 글자 변경 후 옛 review 재사용 시도 | 해시 불일치로 재검토 요구; solution만 바뀌면 review, problem이 바뀌면 solve부터 |
| 실제 답 중복 | vp_r3/run_05/e1.json와 k2.json의 answer_value=18 | 원래 e1은 시험 표현 문제도 있음. 그와 별개로 실제 값 중복 탐지를 확인. 둘 다 통과했다고 가정하는 묶음 단위 시험에서는 동시 납품 금지 |
| 답 비교 동치·오인 | 1/2 대 0.5, 1+3√2 대 1+4√2, 빈 문자열 대 빈 문자열 | 차례로 같음·다름·판정 불가. 마지막 숫자 정규식·부동소수 오차로 승인 금지 |
| 사고 중복 | 동일 원고를 복사해 수치·방향 코드와 답만 다르게 바꾼 묶음 요약 | 답이 다르더라도 같은 판단의 반복을 지목하고 동시 납품에서 제외. 수학적으로 새 원고를 검증했다는 뜻은 아님 |

추가 대조는 13개에 대한 채택률 집계와 섞지 않는다. 묶음 시험에는 bundle.md와 runner의 정확한 값 비교를 함께 사용한다.

## 다음 단계

회귀 세트에 맞춘 수정이 끝나면 프롬프트를 고정한다. 아직 판정에 쓰지 않은 새 원본 소수로 실제 generate → solve → judge → review → bundle을 처음부터 실행한다. 시험 답·기대 판정표는 생성자와 검토자에게 노출하지 않는다. 사례를 추가할 때 출처·버전·원고 해시와 결정 근거를 남긴다. 새 사례에서 발견한 오류는 같은 결함이 가능한 다른 칸도 재검토한다.

새 세트의 학생 수업 사용은 내부 수학·해설 검토를 마친 문항만 대상으로 한다. 원본 경험 여부·풀이 시간·성공 여부·갈라진 식·예상 밖 풀이를 남긴다. 작은 표본을 일반 정답률이나 시험용 품질 보증으로 사용하지 않는다.
